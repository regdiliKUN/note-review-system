# 笔记审查总结系统

> 用本地大模型逐句审校你的中文笔记：挑错别字、纠事实、补知识、理结构，
> 每一条修改都给出理由，你可以逐条保留或丢弃，最后导出修正稿与审阅报告。

一个 **完全离线可跑** 的 Windows 桌面应用：模型跑在你自己的机器上（Ollama），
笔记不上传任何服务器。

---

## 它解决什么问题

个人笔记写久了会积累三类问题：

1. **错与漏** —— 错别字、记错的年份人名、抄漏的前提条件；
2. **散与乱** —— 要点散落在段落里，层级混乱，回头找不到；
3. **图与音** —— 大量截图、语音备忘、录屏，文字检索不到。

通用聊天模型帮不上忙：它只会「通读一遍说个大概」，不会告诉你**第几段第几句**
哪里有问题。本项目的核心是**句级锚点**：模型只返回句子编号，
系统自己定位到原文，所以每一条建议都能精确落到具体位置、可以逐条取舍。

## 主要能力

### 审查
- **七类批注**：错别字 / 事实纠错 / 知识补充 / 表达优化 / 逻辑归纳 / 结构建议 / 存疑待核
- **三种力度**：轻（只挑硬错误）、标准、严格（连措辞一起优化）
- **术语白名单**：专有名词、自造缩写不会被当成错别字改掉
- **全文语境注入**：每段送审都带上标题与大纲，避免把上文定义过的术语当「缺失知识」重复补充
- **同句冲突消解**：同一句的多条改写只保留最严重的一条，不会改出「半句 A 半句 B」
- **低质量过滤**：占位符替换（「……」）、没写理由的整句改写会被自动剔除
- **可中止**：长文档跑到一半发现选错文件，随时停下，已完成部分全部保留
- **可微调**：AI 的改写方向对但用词不合口味，直接在批注里改掉那几个字

### 三种视图
| 视图 | 用途 |
|---|---|
| 全部批注 | 原文 + 彩色标记，点标记看理由，一键保留/丢弃 |
| 修正后版本 | 只应用你采纳的修改，改动处高亮 |
| 重新排版 | 重建标题层级、自动编号、生成目录、合并断行、拆分超长段落 |

**图片永不移动**：文档模型把图片当作段落里的原子片段，
所有文字修改只在文字片段内进行，因此无论改多少遍、重排多少遍，
图片都停在与原文完全一致的位置。

### 输入格式
- **文档**：`.docx` / `.doc` / `.txt` / `.md`（含表格合并单元格、脚注尾注、多级列表）
- **语音**：`.mp3` / `.wav` / `.m4a` / `.flac` … → 自动转写
- **视频**：`.mp4` / `.mov` / `.mkv` … → 抽关键帧 + 转写
- **图片**：支持一次选多张截图，合成一篇「图片笔记」
- **编码**：UTF-8 / GBK / UTF-16 自动识别，中文 txt 不会变成乱码

### 图像审查
逐张生成说明、标注原文位置，并识别三类问题：
与正文不一致、含敏感信息（身份证号/手机号/密钥）、需人工核对。

### 输出
- **正文**：Word / HTML / Markdown / 纯文本（原版、修正版、重排版）
- **审阅报告**：网页版（带统计图表、可直接打印）/ Markdown
- **批注清单**：CSV（`utf-8-sig`，Excel 双击不乱码）

### 其他
- **审查历史**：按文件保存每次结果，可加备注、可对比两次审查的差异、可跨文件搜索
- **环境自检**：模型服务、图像理解、ffmpeg、语音转写、磁盘、历史目录六项一键体检
- **快捷键**：J/K 上下条、A 保留、R 丢弃、Ctrl+Z 撤销、/ 搜索、? 帮助
- **性能**：千段文档切换批注视图 6ms（见 `tests/bench.py`）

## 快速开始

### 1. 准备模型服务

推荐本机 [Ollama](https://ollama.com)：

```bash
ollama serve
ollama pull qwen3:8b          # 主审校模型
ollama pull qwen2.5vl:7b      # 可选：图像理解
```

也可以使用任意 **OpenAI 兼容 API**（在设置里切换，填地址与 API Key）。

### 2. 运行

```bash
python -m venv .venv
.venv\Scripts\activate
pip install -r requirements.txt
python app/main.py
```

需要 Windows 上的 **WebView2 运行时**（Win11 自带，Win10 通常已随 Edge 安装）。

### 3. 打包成 exe（可选）

```bash
pip install pyinstaller
pyinstaller build/笔记审查总结系统.spec
```

## 使用流程

1. **导入** 文档 / 语音 / 视频 / 图片（也可以一次导入多张截图）
2. 点 **开始 AI 审查**，进度条会显示「第几段 / 共几段」与剩余时间估算
3. 右栏逐条看批注：**保留** / **丢弃** / **编辑**（手动微调）
4. 需要结构性调整时，打开右上角 **重新排版** 开关
5. **导出** 修正稿，或导出 **审阅报告** 交给别人看

## 设计取舍

**为什么用句级编号而不是让模型返回原文？**
模型复述原文时几乎一定会改动标点或空格，导致匹配失败。只返回编号（`sid`）
既省 token，又让定位变得确定。

**为什么图片是「原子片段」？**
如果图片是可被编辑的文本占位符，任何一次改写都可能把它挤掉或移动。
把它做成不可编辑的片段，才能保证「改一百遍图片还在原位」。

**为什么长文档要按句切分而不是按段落？**
从 Word 转来的文档常有几千字的单段落，按段落切会直接撑爆上下文窗口。
按句切分后，每片仍带**段落内的绝对句号**，模型返回的 `sid` 依然能精确落位。

**为什么历史用纯 JSON 而不是数据库？**
可读、可备份、可手工修。删目录即清空，不留下看不见的状态。

## 已知限制

- 图像理解依赖多模态模型；没有时图片仍按原位标注，但不做内容识别
- 语音转写需要 `faster-whisper` 或一个 OpenAI 兼容的 `/audio/transcriptions` 端点
- 视频抽帧与音轨提取需要 `ffmpeg`
- 超长文档（>200MB）会被拒绝导入
- 仅在 Windows 上验证；`os.startfile` 等调用是 Windows 专用
