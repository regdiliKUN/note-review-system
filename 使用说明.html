界面长什么样

整个窗口分三块：左边是文档大纲，中间是笔记正文，右边是批注清单。

顶部工具栏

五个视图按钮

全部批注 / 原版笔记 / 修正后版本 / 重新排版 / 图像审查。点一下就能切， 随时来回对比，正文位置不会乱跳。

右侧批注清单

每条批注都写明改了什么和为什么改，底部两个按钮决定 「保留」还是「丢弃」。

底部状态栏

实时显示待定 / 保留 / 丢弃各多少条，右下角是导出按钮。

三个入口图标怎么认（v1.1.1 重新绘制）

三个图标统一 24×24 线性风格、统一线宽与圆角，含义一眼可分：

  • 导入文档（蓝色按钮，左上角）：箭头朝下落入托盘 —— 把文件「收进来」。
  • 导出（右下角）：箭头朝上送出托盘 —— 把结果「送出去」。
  • 设置（右上角齿轮）：完整的齿轮 —— 只负责设置，不承担任何导入导出功能。
之前的问题已修掉：导入按钮曾误用「上传/导出」图标、导出按钮曾误用「下载/导入」图标， 两个语义正好反着；右上角齿轮的图形路径被截断，只画出半圈波浪线。现在三者已彻底分开， 不会再混用。

完整操作流程

1. 导入文档

点左上角「导入文档」，选择 .docx、.txt 或 .md 文件。 导入后左侧会列出文档大纲、段落数、图片数。

图片不会丢（v1.1 已修复 .doc 图片丢失）。原文里的图片在解析、批改、重排、导出的每一步都被当作 「不可拆分的一块」单独保存，按原始格式与清晰度落盘（PNG/JPEG 原样字节，不压缩、不转格式）， 文字怎么改都只会动文字，图片停在原位。段落中间夹着图片的混排情况也一样安全。

.doc（Word 97-2003）此前只能读到文字、图片全部丢失，且 WPS 生成的 .doc 还会中文乱码； 现已重写解析：从文档的 Data / WordDocument 数据流中按原始字节无损抠出全部图片， 再按正文里的图片占位符（0x0001/0x0008）原位插回。 实测一篇 73MB 的 ZBrush 笔记可完整还原 488 张图片，中文正常显示。

2. 让 AI 审校

点「开始 AI 审查」，模型会通读全文，从七个角度找问题：

批注类型说明
错别字错字、别字、同音误用、标点不规范
事实纠错事实、数据、年份、人名、概念写错了
知识补充缺少的关键定义、前提、例子、背景
表达优化啰嗦、指代不清、语序乱、太口语
逻辑归纳把散落的同类要点合并提炼
结构建议层级混乱、缺标题、段落切分不当
存疑待核模型没法确定，需要你自己核实

正文里会出现彩色高亮，颜色对应批注类型；右侧清单里每条都带 修改前后对照和修改理由，右上角的小圆点表示严重程度 （红＝重要，黄＝一般，灰＝参考）。

图像也进审查体系（v1.1 新增）

除了文字，程序会把文档里的图片也当成审查对象。审查完成后点顶部 「图像审查」 标签页， 能看到每张图片的缩略图、说明和它在原文中的位置。

逐图说明 + 定位

为每张图生成一句简要说明（截图 / 图表 / 流程图 / 公式 / 手写笔记…）， 并标注它所在的段落、属于哪个小节。

三类问题自动标红

含敏感信息（手机号、证件号、密钥等）、与正文不一致（图不对题）、 需人工核对（模糊、看不清、信息不完整）。

v1.1.1 起已内置视觉模型，开箱即用。本机已装好 qwen2.5vl:7b， 并已写入设置（设置 → 视觉模型），点「开始 AI 审查」就会自动逐图识别，无需再手动配置。 想换更强的模型，在「设置 → 视觉模型」里改成 llava、minicpm-v 或 OpenAI 兼容的 gpt-4o 即可；清空则退回「只标注位置、全部人工核对」的模式， 仍然绝不丢图、也不会报错。
关于速度：每张图约 2～3 秒，程序会同时处理 3 张。像 488 张图的笔记， 整篇识别大约需要 15～20 分钟，进度条会实时显示「正在理解图片 128/488…」。 原图不会因为识别而变模糊 —— 压缩只作用于「送模型看的那份副本」， 磁盘上的原图、界面显示和导出始终保持原始格式与清晰度。

图像问题会和文字批注一起进入右侧问题清单，可逐条追溯；导出的「修正后版本 / 重排版版本」 末尾也会自动附上「图像说明与核对」清单，让总结同时覆盖文字与图像两部分。

审查历史：同一个文件不用审第二遍（v1.1.2 新增）

每完成一次审查，结果都会自动存到本地。下次再打开同一个文件， 程序会直接把上次的批注、总结、图像审查结果接回来，不再调用模型， 省下十几分钟甚至更久。

按文件区分

历史跟「文件路径」绑定，A 笔记和 B 笔记互不干扰； 同一个文件审过几次，就攒下几条记录，可以随时回看、来回切换。

文件改过不会乱套

如果文件在审查之后被改动过，程序不会偷偷套用旧结果， 而是提示「文件已变化」，由你决定是回看旧记录还是重新审查。

怎么看历史

点右上角的 时钟图标（就在齿轮左边），会打开「审查历史」面板，里面能看到：

  • 存储位置：完整路径，旁边有 「打开文件夹」 按钮，一键用资源管理器打开；
  • 当前文件的每一条记录：时间、批注数、图片数、用的模型、耗时；
  • 每条右侧的 「载入」 可以直接切到那次的结果，「删除」 删掉单条；
  • 底部 「清空本文件历史」 一次清干净。
存储位置默认就在程序目录里：I:\workbuddy\笔记审查总结系统\history。 也就是说，程序装在哪，历史就存在哪，不会偷偷往 C 盘塞东西。 设置里也能看到这个路径，并同样带「打开文件夹」按钮。 想换地方，点「更改目录」选一个新文件夹即可（已有的旧记录不会自动搬过去）。

存储格式（想备份或迁移时看）

纯 JSON 文件，UTF-8 编码，没有任何数据库，拷走目录就等于备份：

history\
  └─ Zbrush笔记_a1b2c3d4e5\          ← 每个文件一个文件夹（文件名 + 路径哈希）
       ├─ meta.json                   ← 这个文件的路径、大小、修改时间 + 历次记录索引
       ├─ 20261023-175301.json        ← 一次审查的完整快照
       └─ 20261022-201133.json        ← 更早的一次

一次快照里存的东西：
  批注列表（anns）· 总结（summary）· 图像审查结果（image_report）
  模型名 · 视觉模型名 · 耗时 · 当时文件的大小与修改时间

每个文件默认保留最近 8 次，超出的旧快照会自动删掉，避免越攒越大。 想多留几次，改 data\config.json 里的 history_keep 即可。

3. 逐条取舍

这是整个程序的核心。对每一条批注，你有三种做法：

  • 点 保留 —— 这条修改进入「修正后版本」
  • 点 丢弃 —— 这条不要，原文保持不变
  • 先不管 —— 保持「待定」，最后再统一处理

右侧顶部的 全部保留 / 全部撤销 可以一次性处理所有批注。 清单上方还能按「待处理 / 已保留 / 已丢弃」筛选。

快捷键：按 1234 快速切换四个视图； 选中某条批注后按 Enter 保留、按 Delete 丢弃。

4. 需要重新排版吗？

工具栏右上角有个「重新排版」开关，默认关闭。打开后会自动生成第四个视图：

  • 自动生成 内容提要 和 要点（把整篇笔记归纳成几句话）
  • 生成 目录，标题按「一、/（一）/ 1.」自动编号
  • 补齐缺失的标题层级，合并被硬换行切断的句子
  • 规整多余空格和重复标点
重排只调整「怎么呈现」，不打乱「讲什么」。 段落顺序完全不动，图片跟着它所在的段落走， 所以原来在哪张图旁边的文字，重排后还在那张图旁边。

具体项目可以在右上角齿轮「设置」里逐项开关。

5. 导出

点右下角「导出」，选格式和版本：

格式适合
Word（.docx）要交作业、交报告、继续编辑 —— 图片已嵌入文档
网页（.html）要发给别人看、要打印 —— 双击就能在浏览器打开
Markdown（.md）要放进 Obsidian / 笔记软件 —— 图片会单独存一个文件夹
纯文本（.txt）只要文字，图片用「[图片N]」占位

版本有三种：修正后版本（采纳了你保留的修改）、 重排版版本（再加排版和提要）、原版笔记（完全没动过的原文）。 导出完成后会自动帮你打开文件所在文件夹。

常见问题

右上角小圆点是灰的 / 红点，AI 审查点不动

说明程序连不上 Ollama。先确认 Ollama 在运行：开始菜单里找到 Ollama 打开一次， 它会在后台常驻。然后点右上角齿轮进「设置」，点一下「测试连接」， 看到「连接成功」就可以了。如果装的是别的服务，把「服务地址」改成对应地址。

模型怎么选？qwen3:8b 和更大的模型差在哪

顶栏右侧的下拉框可以切换。8B 级别的模型速度快（一篇几千字的笔记几十秒出结果）， 够用来找错别字、标点和明显的表达问题； 27B 级别的模型判断更准、能发现更多事实性问题，但速度会慢好几倍。 日常改稿建议先用快的，重要文档再换大的重跑一次。

批注说得不对怎么办

直接点「丢弃」就行。模型给的是建议，不是判决 —— 每条都写明了理由， 就是为了让你能一眼判断该不该采纳。丢弃的批注不会影响原文， 也不会进入导出结果。

原文的图片会不会在批改过程中被弄丢或挪位置

不会。程序在解析时就把每张图片按原始字节单独抽出来存成文件（保留原格式，不做有损压缩或强制转格式）， 并在正文里标记它「夹在哪两个文字片段之间」。 批改只替换文字片段内部的内容，图片所在的片段既不会被删、也不会被移动。 重新排版时段落顺序不变，图片自然跟着原段落走。 导出时图片按原位重新嵌入。图片不会集中到文末，也不会被占位符或链接替代。

为什么以前 .doc 文件的图片全没了，现在还会吗

以前 .doc 只做了「文字提取」，图片数据所在的 Data 流根本没读，所以一张都出不来； WPS 生成的 .doc 还会因为编码判断错误而整篇乱码。v1.1 已重写 .doc 解析： 从 Data / WordDocument 流无损抠出全部 PNG/JPEG， 并按正文占位符原位插回，同时修正了编码判断。现在 .doc 的图片和中文都能正常还原。

支持 .doc 老格式吗

支持直接读 .doc（Word 97-2003 二进制格式，程序内置解析器直接提取正文与图片， 图片按原位还原）。 .docx、.txt 和 .md 也可以直接导入，Markdown 里的图片引用也会一并读进来。

导入的文件和导出的结果存在哪

导入时图片会被复制一份到 I:\workbuddy\笔记审查总结系统\data\assets\ 下做缓存， 原文件不会被修改。导出默认存到你选择的位置；如果直接回车确认， 会存到 I:\workbuddy\笔记审查总结系统\导出结果\。程序配置在 I:\workbuddy\笔记审查总结系统\data\config.json， 审查历史在 I:\workbuddy\笔记审查总结系统\history\ （右上角时钟图标 → 「打开文件夹」可直接定位）。

审查历史会不会把 C 盘塞满

不会。历史默认就写在程序自己所在的目录（本机是 I 盘），跟程序放在一起。 只有当 I 盘不可写、程序目录也写不进时，才会回退到 %LOCALAPPDATA%\NoteReview\history， 并且会在「审查历史」面板顶部用黄色提示明确告诉你。 每个文件只保留最近 8 次，占用很小。

能同时处理多篇笔记吗

一次处理一篇。处理完导出，再导入下一篇。之前打开的文档会留在欢迎页的「最近打开」里。
